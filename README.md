# Pocket Option — ابزار جمع‌آوری دیتاست معاملات ۳ ثانیه‌ای

این پروژه یک ابزار کمکی برای **حساب دمو (Demo)** Pocket Option است که:

1. با Playwright به نسخهٔ وب Pocket Option متصل می‌شود و ترافیک WebSocket را شنود می‌کند.
2. از روی تیک‌های قیمت، سرعت/شتاب حرکت قیمت و ویژگی‌های کندل ۱ دقیقه‌ای را در لحظه محاسبه می‌کند.
3. با فشردن یک کلید توسط شما (`c` برای CALL، `p` برای PUT) لحظهٔ ورود به معامله را با تمام ویژگی‌های فنی آن لحظه ثبت می‌کند.
4. بعد از ۳ ثانیه (زمان انقضای معاملهٔ شما)، نتیجهٔ معامله را Win=1 / Loss=0 لیبل زده و در `data/trades_dataset.csv` و `data/trades_dataset.sqlite3` ذخیره می‌کند.

خروجی این ابزار یک دیتاست آموزشی (Training Dataset) است که می‌توانید بعداً با آن یک مدل یادگیری ماشین (مثلاً LightGBM/XGBoost یا یک شبکهٔ ساده) آموزش دهید تا الگوی تصمیم‌گیری شما را یاد بگیرد.

## نصب

```bash
pip install -r requirements.txt
playwright install chromium
```

## اجرا

```bash
python main.py
```

1. مرورگر Chromium باز می‌شود و به صفحهٔ دموی Pocket Option می‌رود.
2. **به‌صورت دستی** با حساب دموی خودتان لاگین کنید.
3. وقتی چارت و قیمت‌ها کاملاً بارگذاری شدند، در ترمینال Enter بزنید.
4. از این‌جا به بعد، در ترمینال:
   - `c` + Enter → ثبت معاملهٔ CALL در همین لحظه
   - `p` + Enter → ثبت معاملهٔ PUT در همین لحظه
   - `q` + Enter → خروج امن (داده‌ها قبل از خروج ذخیره می‌شوند)

## نکتهٔ مهم دربارهٔ فرمت پیام‌های WebSocket

پروتکل داخلی Pocket Option مستند رسمی ندارد و ممکن است تغییر کند. اسکریپت به‌طور
پیش‌فرض تمام فریم‌های خام دریافتی را در `data/raw_ws_frames.log` ذخیره می‌کند
(`DEBUG_LOG_RAW_FRAMES = True` در `config.py`). اگر تابع
`extract_ticks_from_payload` در `src/browser_session.py` تیک‌ها را درست
تشخیص نداد:

1. چند دقیقه اسکریپت را اجرا کنید تا `raw_ws_frames.log` پر شود.
2. نمونه‌های واقعی پیام‌ها را در آن فایل ببینید.
3. الگوی `_looks_like_tick_row` / `extract_ticks_from_payload` را با فرمت واقعی هماهنگ کنید.

## ساختار پروژه

```
config.py                     تنظیمات مرکزی (تایم‌فریم، مسیر فایل‌ها و ...)
main.py                       نقطهٔ ورود؛ هماهنگ‌کنندهٔ asyncio بین بخش‌ها
src/browser_session.py        بخش ۱: مرورگر + شنود WebSocket
src/feature_engineering.py    بخش ۲: بافر تیک (سرعت/شتاب درصدی)، Stall/Spike، ویژگی‌های شکلی کندل
src/market_structure.py       بخش ۲ (تکمیلی): سوئینگ، لگ، حمایت/مقاومت، روند، شکل نسبی چارت
src/state_tracker.py          بخش ۳: تاریخچهٔ Win/Loss و وین‌ریت لحظه‌ای
src/data_logger.py            بخش ۴: ثبت معامله، لیبل‌گذاری، ذخیره در CSV/SQLite
data/                         خروجی‌های تولیدشده (CSV، SQLite، لاگ خام) — در گیت ignore شده‌اند
```

## فلسفهٔ داده: همه‌چیز نسبی است، نه مقدار خام قیمت

مدل باید دقیقاً مثل خود شما با نگاه‌کردن به **شکل** چارت تصمیم بگیرد، نه با
حفظ‌کردن اعداد قیمت یک نماد خاص. به همین دلیل **هیچ ستونی در دیتاست مقدار خام
قیمت ندارد** (به‌جز ستون‌های `meta_*` که فقط برای ردیابی/دیباگ‌اند و نباید به
مدل داده شوند). ویژگی‌های نسبی که در هر ردیف ثبت می‌شوند:

| گروه | ویژگی‌ها |
|---|---|
| سرعت/شتاب | `velocity_pct`, `acceleration_pct` و نسخه‌های هموارشدهٔ آن‌ها (درصد تغییر قیمت بر ثانیه، نه مقدار مطلق) |
| حرکت ناگهانی | `spike_zscore` (آیا حرکت لحظه‌ای نسبت به نوسان عادی اخیر غیرعادی است) |
| موقعیت در کندل جاری | `price_position_in_candle`, `distance_from_open_ratio` |
| توقف نشانگر | `stall_count_in_candle`, `last_stall_position_in_candle` |
| هم‌جهتی تیک با کندل | `tick_vs_candle_alignment` (آیا حرکت ۳ ثانیه‌ای هم‌جهت روند کندل دقیقه‌ای است یا در حال واگرایی) |
| شکل کندل جاری/قبلی | `candle_curr_*`, `candle_prev1_*` (نسبت بدنه به سایه، نسبت سایهٔ بالا/پایین) |
| مقایسهٔ کندل‌های اخیر | `candle_size_ratio_prev{1,2,3}`, `candle_color_match_prev{1,2,3}` |
| نوسان | `volatility_ratio_short_long` (انبساط/انقباض نوسان: ATR کوتاه به ATR بلند) |
| شکست ساختار | `broke_prev_candle_high/low`, `broke_recent_swing_high/low` |
| حمایت/مقاومت | `dist_to_resistance_atr`, `dist_to_support_atr` (فاصله نرمال‌شده با ATR) |
| وجود سوئینگ | `has_swing_data`, `swing_range_defined` (پیش‌نیاز ویژگی‌های زیر؛ در ابتدای اجرا ۰ است) |
| کندل نسبت به سوئینگ | `candle_range_to_swing_range_ratio` (محدودهٔ کندل جاری چه سهمی از کل محدودهٔ سوئینگ دارد) |
| لگ (Leg) | `leg_direction`, `leg_length_in_candles` (طول لگ برحسب تعداد کندل، نه ثانیه خام)، `leg_range_to_swing_range_ratio` (محدودهٔ لگ فعلی نسبت به محدودهٔ کل سوئینگ)، `leg_extension_ratio` (نسبت به میانگین چند لگ قبلی)، `fib_retracement_of_prev_leg` |
| روند | `trend_regime` (۱=صعودی، ۰=رنج، ۱-=نزولی)، `trend_regime_ready` |
| استریک | `candle_color_streak` |
| عدم‌تقارن سایه | `wick_asymmetry_current`, `wick_asymmetry_relative` |
| شکل کلی چارت | `chart_shape_json` — دقیقاً همان «پنجرهٔ دیداری» که روی صفحهٔ پلتفرم دیده می‌شود: ۲۰ کندل آخر (شامل کندل در حال شکل‌گیری فعلی به‌عنوان لبهٔ راست) که محور قیمتش با همان پنجره Auto-Scale می‌شود (۰ تا ۱ نسبت به های/لوی خودِ همین پنجره) — بدون هیچ مرجع بیرونی (نه قیمت، نه ATR، نه شمارهٔ زمانی). ترتیب لیست از قدیم به جدید است؛ همین ترتیب جای هر شمارهٔ زمانی را می‌گیرد. برای یادگیری الگوهای بزرگ (مثلث، پرچم، دوقلو و ...) دقیقاً همان‌طور که چشم شما می‌بیند |
| تاریخچهٔ معاملات | `recent_result_1..3`, `rolling_winrate`, `overall_winrate` |

هنگام آموزش مدل، ستون‌های `direction` (ورودی معتبر: تصمیم شما) و `result`
(لیبل نهایی: خروجی) را نگه دارید و همهٔ ستون‌های `meta_*` را قبل از آموزش حذف
کنید. برای استفاده از `chart_shape_json` در مدل، آن را با
`json.loads(row["chart_shape_json"])` به لیستی از دیکشنری‌ها (`o,h,l,c,bullish`
برای هر کندل) تبدیل کنید.

نکته: چون سوئینگ‌ها فقط با یک کندل تأخیر تأیید می‌شوند (ماهیت ذاتی تشخیص
سوئینگ)، ستون‌های مرتبط با ساختار (`leg_*`, `dist_to_*`, `trend_regime`) در
اولین دقایق اجرای اسکریپت مقدار `None`/غیرقابل‌اتکا خواهند داشت تا سوئینگ کافی
جمع شود؛ از ستون‌های `has_swing_data` و `trend_regime_ready` برای فیلتر کردن
ردیف‌های ناقص استفاده کنید.

تنها دو ستون در کل دیتاست مقدار خام قیمت دارند: **`meta_entry_price`** و
**`meta_exit_price`** (فقط برای محاسبهٔ داخلی نتیجه و ردیابی/دیباگ). سایر
ستون‌های `meta_*` (`meta_symbol`, `meta_entry_timestamp`, `meta_exit_timestamp`)
قیمت نیستند، فقط زمان/نماد برای ردیابی‌اند.

## محدودیت‌ها و هشدارها

- این ابزار فقط برای **حساب دمو** طراحی شده؛ قبل از هرگونه استفاده روی حساب واقعی،
  قوانین و شرایط استفادهٔ (Terms of Service) بروکر خود را بررسی کنید.
- این اسکریپت هیچ معامله‌ای را **به‌صورت خودکار در پلتفرم باز نمی‌کند**؛ فقط داده
  را برای آموزش مدل ثبت می‌کند. ورود/خروج واقعی معامله را همچنان خودتان در
  رابط Pocket Option انجام می‌دهید (یا در آینده، بعد از تست مدل، می‌توانید یک
  ماژول کلیک خودکار روی دکمه‌های CALL/PUT اضافه کنید).
- دقت لیبل‌گذاری به دقت تشخیص فرمت پیام‌های WebSocket بستگی دارد؛ حتماً چند صد
  ردیف اول دیتاست را دستی با آنچه در پلتفرم دیده‌اید مقایسه کنید.
